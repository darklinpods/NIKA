# 关键决策记录 (Decisions)

记录项目中的重要技术选型、架构决策和设计选择，包括背景、选项对比和最终决策原因。

## 格式说明

每条决策包含：
- **日期**：YYYY-MM-DD
- **决策主题**：简短标题
- **背景**：为什么需要做这个决策
- **选项**：考虑过的方案及其优缺点
- **决策**：最终选择的方案及原因
- **影响**：对项目的长期影响

## 2026-06-03: 证据管理采用“原始证据 / 派生数据 / 输出文档”三层范式

### 背景

NIKA 的证据相关逻辑已经覆盖上传、OCR/解析、当事人提取、案由识别、发票提取、事实摘要、证据整理、缺失检测、证据目录和文书生成。功能本身可用，但此前存在职责混用：

- 原始证据和生成文档都存放在 `CaseDocument`
- 多个 AI 流程读取全部文档，可能把生成文档再次当作证据输入
- `caseFactSheet` 同时被当作 Markdown 事实摘要和 JSON 数据容器
- 证据整理和证据目录生成存在逻辑分叉

如果不先稳定范式，后续新增案件类型、证据项编辑或文书导出时会继续扩大混乱。

### 选项

1. **继续沿用现有字段，只靠调用处约定区分**
   - 优点：改动最少
   - 缺点：约定分散，容易再次出现证据污染和字段混写

2. **一次性新增完整证据模型，如 EvidenceItem / EvidenceAnalysis / GeneratedDocument**
   - 优点：领域建模清晰
   - 缺点：迁移范围大，会牵动 UI、接口、历史数据和文书生成流程

3. **先建立三层范式，并做最小结构调整**
   - 优点：快速止住混乱，兼容旧数据，为后续建模留出口
   - 缺点：整理结果暂未完全持久化，仍需后续演进

### 决策

选择 **方案 3：先建立三层范式，并做最小结构调整**。

三层范式如下：

1. **原始证据层**
   - 真源是 `CaseDocument(category='Evidence')`
   - 证据 AI 读取必须通过 `evidenceRepository`

2. **证据派生数据层**
   - 发票清单、索赔试算等机器派生 JSON 存放在 `Case.evidenceData`
   - 前端通过 `client/utils/evidenceData.ts` 统一读写

3. **输出文档层**
   - 证据目录、策略分析、起诉状等为输出物
   - 输出物不得默认反向喂给证据抽取流程

### 原因

- 这一步能立即解决“AI 上下文污染”和“字段职责混乱”两个主要风险
- `evidenceData` 可以兼容现有 SQLite 和 Prisma 结构，不需要大规模迁移
- `caseFactSheet` 保留为律师可读事实摘要，更符合 UI 使用方式
- 证据整理服务抽取后，页面按钮和 Agent 工具能保持一致口径

### 影响

- 新增 `server/src/utils/evidenceRepository.ts`
- 新增 `Case.evidenceData`
- 新增 `client/utils/evidenceData.ts`
- 新增 `server/src/services/evidenceOrganizerService.ts`
- 后续所有证据相关功能必须先判断属于三层中的哪一层

## 2026-06-03: 项目协作采用 docs 六件套作为长期工作范式

### 背景

NIKA 是长期迭代项目，涉及 AI、法律业务、证据管理、文书生成、前后端和数据库。单靠对话上下文容易丢失当前现场和决策原因。

用户希望参照 `word-assist/docs` 的 Hermes-Team 简化范式，在 NIKA 中建立同样的工作方式。

### 决策

建立 `docs/` 六件套：

- `CONTEXT.md`：项目背景、架构、约束和关键范式
- `CURRENT.md`：当前现场、最近工作、待验证事项
- `TASKS.md`：任务清单、优先级、状态和验收标准
- `CHANGELOG.md`：开发日志
- `DECISIONS.md`：关键决策记录
- `AGENTS.md`：AI 协作开发规范

### 原因

- `CURRENT.md` 解决“下次接不上现场”的问题
- `TASKS.md` 解决“做着做着范围膨胀”的问题
- `DECISIONS.md` 保留为什么这样做，避免未来反复推翻
- `AGENTS.md` 把协作规则从口头要求变成项目规则

### 影响

- 今后每轮开发开始前，应先阅读 `docs/CURRENT.md` 和 `docs/TASKS.md`
- 每轮完成后，至少更新 `docs/CURRENT.md`；涉及功能、决策、任务状态时同步更新对应文档
- 根级 `AGENTS.md` 仍保留仓库级硬规则，`docs/AGENTS.md` 作为持续协作范式说明
